# Prepare an explainer video

This skill belongs to the Explainer Video Workshop, the repository that contains it; resolve every path from the repository root. Require the maintained method and scorecard to be readable before proceeding.

## Route and procedure

For a preparation request, read `methods/prepare-explainer-run.md` and `scorecards/preparation-quality.md` under the workshop root. Read only the needed templates. Use `library/source-map.md` and `library/manifest.json` for evidence and renderer decisions; do not load the entire research corpus. Read the workshop's git-ignored `local/brand.md` before choosing the visual system. If it is missing, first ask whether the user has brand guidelines to point to, and record the answer (see `methods/apply-brand.md`).

Produce the requested preparation package under the user's output path, or `outputs/<topic>/`. A viable package includes a sourced claim map, audience and learning target, script, feasible scene/shot timing, a renderer decision, audio/pilot plans, resumable state, and a filled `production-prompt.md`. Use `templates/production-prompt.md` for that executable handoff; do not merely give the next agent another preparation request.

Use reasonable stated defaults for reversible presentation choices. If an essential source is absent or unreadable, return one concise intake handoff naming the missing evidence and dependent claims. Continue only on a clearly narrowed source-backed scope. Do not create empty downstream production files or invent the missing source, prompt, or result.

Compute narration timing per scene: words / stated WPM plus breathing and learner-processing pauses. Check that feasible scene windows sum to the target. Global duration arithmetic alone is insufficient. These are estimates until approved audio exists; audio changes invalidate its dependent timing, captions, cues, and reviews.

Apply the scorecard, including its critical failures, before calling the package prepared. Do not claim audio, a pilot, a render, playback, synchronization, or learning outcomes that were not observed. Public source code and skill instructions do not prove a creator used them. Workshop-authored prompts are reconstructions, never exact recovered creator prompts.

## Boundaries

If the user requests production from an existing viable package, follow its filled production prompt and the workshop's production route; do not restart preparation without a changed dependency. Research-only requests use the source map and audit instead. Existing edits or resume work start from actual artifacts and state.

An eight-hour value is an optional production ceiling, not a required runtime or quality guarantee. Record measured time/cost when available; prompts do not enforce those limits. Preserve the user's authorized autonomy and stop at acceptance. Do not purchase, publish, upload private material, or contact creators without authorization.

## Evidence

Preparation is the tested capability. Full sustained video production is unvalidated until an actual artifact run and its required reviews exist.
